## 4. P1-1 Architecture Guard（PR-07）——推荐立即开始

### 为什么是最高价值的工程项
审计 §3.3 的结论是：ECH 缺陷之所以逃过所有测试，是因为它落在
**"前端测方法名 / 后端测别的方法 / ACL 测名单格式" 的三层接缝**上。
这不是测试数量问题，是**没有人在接缝处负责**。`重构实施间断性指导建议.md` 第 28 条
要建的 Architecture Guard 正是这个角色，而它**至今没建**（台账 §5 项 14 仍 ⬜）。

### 范围
新增 `tests/arch-guard.sh`（POSIX sh，**不需要 ucode/node**，按纲领要求）。
首批守卫建议就包含本次审计发现的**契约闭合性检查**：

1. **ACL ↔ 后端方法双向差集为空**（本次已用 Python 验证过，把它固化）
2. **前端 `rpcCall` 的方法名集合 ⊆ 后端定义集合**
3. **每个证书上传按钮的 filename 都有对应后端 case** ← 直接针对本次缺陷
4. 7 条架构边界（生成器/解析器/适配器不读 UCI 等）固化为可执行断言
5. 无野字符号、无死代码符号

### 验收标准
- `tests/arch-guard.sh` 在纯 POSIX sh 下可运行，退出码可用于 CI
- **每一条守卫都必须反向验证过**（故意破坏 → 变红 → 恢复），这是本项目的硬标准
- 接入 `tests/run.sh` 与 CI
- 把"3"这一条在 ECH 修复**之前**接上去，确认它**能抓到当前这个 bug**——这是最好的验收

### 风险
- 中：守卫本身可能过度耦合实现细节（比如 grep 具体的代码文本）。
  **缓解**：优先从**数据/清单**派生断言（解析 switch 的 case 列表），而不是匹配代码格式。
